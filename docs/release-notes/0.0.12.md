MarkTodo loads on mobile again, Today is now Agenda, Recent is gone, finished work reads newest-first everywhere, and long sections stop at twenty rows instead of drawing your whole vault.

**MarkTodo loads on mobile again**
- On a phone in dark mode, 0.0.11 failed to load with "Failed to load plugin". Obsidian's own mobile dark palette writes `--background-primary: #000` — three-digit shorthand — and MarkTodo's colour reader only accepted six digits, so it threw before the plugin finished starting.
- A theme colour is now resolved the way the browser resolves it, so shorthand hex, `rgb(...)`, `color-mix(...)` and plain colour names all read. Anything still unreadable falls back to the light or dark default rather than taking the plugin down with it.
- Nothing to do: install and it loads.

**Today is now Agenda**
- The pane leads with everything **overdue**, and has since 0.0.9. No reading of "Today" covers a todo you missed three weeks ago, so the name was telling you the wrong thing about what you were looking at. Agenda is what is late plus what is due now.
- **The command id changed** (`open-today` becomes `open-agenda`). If you had a hotkey bound to "Show today", bind it again under **Show agenda**.
- The pane's stored sort, grouping, folds and which pane you had open reset once, to their defaults. They are back to being remembered from the first time you set them again.

**Recent is gone**
- Recent showed what you finished in the last seven days. With Done now reading newest-completed first and paging rather than stopping at an arbitrary week (below), the Todos view's Done section does the same job without the cutoff.
- It also gives the other segments room: **Agenda, Upcoming and Reminders** fit one row on a phone, where four wrapped to two.

**Done reads newest-completed first**
- Every Done section and every Done column now orders by when the todo was finished, newest at the top — in the Todos view, in a project's list, and on every board. It ignores whatever sort you have set, because every other order over finished work answers a question nobody asks.
- **`done @` now records the minute**: `done @ 2026-09-22 14:07`. Stamps already in your notes keep their bare date and are never rewritten — the minute they would gain is the minute you re-saved, not the minute you finished — so they read as that day's start.
- **A Done row can no longer be dragged to reorder.** Its position in the file no longer says anything about where it appears, so a drag would write an order the list refuses to show. Dropping a todo *into* Done still works, and still marks it done.

**Long sections stop at twenty**
- Every section and every board column draws at most **20 rows**, then offers **Show 20 more**. The heading still counts the whole section, so `Done 412` still says 412.
- This is about what gets drawn, not what gets found: a vault with a thousand finished todos was building a thousand rows every time the view opened, and Done is rarely the reason you opened it.
- What you have opened stays open while you are on that list, including when something re-indexes underneath you. Navigating to another project, segment or view starts back at twenty.
